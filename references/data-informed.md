# Data-Informed Design

From "Mind the Gap: User-Centered Design in (Large) Organizations" (Conversions@Google, 2019) and "Obvious Always Wins" (2017).

## The pairing rule

**"Quantitative will tell you what happened; qualitative tells you why."** Never recommend a redesign from analytics alone or interviews alone. Funnels, survival analysis, and session data locate the problem; talking to users explains it. The Google+ navigation redesign used both before shipping.

## Measure outcomes, not surface actions

Conversions, completions, retention, revenue — not clicks, installs, or time-on-site. Wrong metrics create the gap between what the company optimizes and what customers need. When a user justifies a design with a metric, check whether it's an outcome or a vanity proxy.

## The three gaps (why good orgs ship bad design)

1. **Company–customer distance** — Conway's Law: you ship your org chart. Features reflect internal structure, not user problems.
2. **Purpose vs. form** — elements added for legal, competitive, or consistency reasons rather than user need. Ask of every screen element: whose problem does this solve?
3. **First-use-to-fandom gap** — friction before value drives abandonment. Map how long a new user works before the product proves itself.

## The three remedies

1. **Awareness** — notice when the customer's voice has left the room.
2. **Right metrics** — outcome metrics, instrumented honestly.
3. **Customer proximity** — "Spend time with customers. Do it regularly, do it often."

## Data licenses conviction

"Products without a point of view have no point." Consensus produces mush; evidence produces conviction. When research supports it, breaking platform convention is legitimate — bottom navigation shipped against Android's own guidelines because the data said so. Obvious is only obvious in retrospect, and it takes heavy iteration to get there (Apple reviewed 50+ variants of a single hardware button).

## Find the bandaid

Workarounds are design bugs filed by users in behavior instead of words: exported spreadsheets, browser bookmarks into deep pages, support macros, copy-paste rituals. Ask what users do *around* the product.

## Applying this in a review

- Ask what outcome metric the design is accountable to; if none, that's the first finding.
- Ask what qualitative signal supports the current design; if the answer is "stakeholder preference," name the gap it reflects.
- Propose the measurement plan alongside the design change: what number should move, by roughly when.
